# Multi-Pics Cases

Deterministic multi-image precision dataset for `L0.5` requests with 1 to 40 images.

This dataset is the standard bundled fixture set used by `multi_pics_eval.py` and the default three-mode regression flow in `run_full_regression.py`.

## Dataset rules

- Case `01` contains 1 image and uses a `YES` or `NO` question.
- Cases `02` to `40` contain `N` images and ask for exactly one target image index.
- Shape and color combinations are unique within each case.
- A shape may repeat inside a case, but repeated shapes always use different colors.
- Files are generated by `generate_dataset.py` with seed `20260426`.

## Included files per case

- `question.md`
- `answer.md`
- `answer.json`
- `*.jpg` images ordered by filename prefix

## Maintenance contract

Each case directory is consumed structurally by `multi_pics_eval.py`. Keep these conventions stable:

- `question.md`: natural-language prompt shown to the model
- `answer.md`: human-readable reference answer
- `answer.json`: structured answer used by the scorer
- image files: ordered visual inputs for the case

If you modify prompts or answers, update `answer.json` together with the natural-language files. Do not change only `answer.md`.

## Regression usage

By default, the precision skill reuses this dataset across all three transport modes:

- `base64`
- `local_path`
- `http`

This means L0.5 failures should be interpreted together with transport mode and extraction status, not only with final correctness.

## Failure attribution hints

- extracted answer is valid but wrong: prefer `Model Capability Limitation`
- answer exists but cannot be reduced to the required short form: prefer `Output Format / Protocol Issue`
- request failure, timeout, HTTP/media access issue: prefer `Engineering Error`
